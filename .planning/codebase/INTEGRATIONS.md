## Implemented Local Integrations

### npm package / CLI

- Entry point: `bin/adp.js`.
- Binaries: `adp`, `saf`.
- Package metadata: `package.json`, `package-lock.json`, `VERSION`.
- Release artifact: `npm pack` tarball generated by release workflow.

### GitHub Actions

- `.github/workflows/ci.yml`: validation/test matrix for pushes and pull requests.
- `.github/workflows/release.yml`: `npm test`, `npm pack`, upload artifact, attach to GitHub release.
- Release tags: semver `v*.*.*` and legacy transition `v*.*.*.*`.

### Spec-Kit / ATLAS artifacts

- `.specify/` contains Spec-Kit presets/templates/scripts/workflows.
- `specs/<feature-slug>/` contains canonical feature artifacts.
- `.claude/skills/` and `.agents/skills/` contain packaged ATLAS and SAF skills.

## Specified / Optional Tooling

These tools may be used by agents or target projects but are not SAF runtime dependencies unless a concrete local config says so:

- GitNexus, Serena, Semble, Context7.
- GSD, GStack, Superpowers skills.
- Promptfoo, Playwright, browser/manual QA tools.

## Data Storage

- File-based only; no database or cloud storage integration.
- Mutable state lives under `.ai/state/`, `.ai/claims/`, `.ai/locks/`, `.ai/signals/`, and `.ai/context-packs/`.

## Authentication / Secrets

- No application auth provider exists.
- No repository secret values are required for local validation.
- `.gitignore` excludes `.env`, `*.env`, `*.pem`, and `*.key` patterns.

## Monitoring / Observability

- SAF observability is local and file-based: `saf signal` appends to `.ai/signals/current-period.jsonl`.
- No hosted logging or error-tracking service is configured.
