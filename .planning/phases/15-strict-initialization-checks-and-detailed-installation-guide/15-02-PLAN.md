<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| filesystem (read) → CheckReport (in-memory) | The module reads `repoRoot`-rooted paths only; no user-supplied raw path becomes a `path.join` first arg. Parse errors from untrusted YAML/JSON content are caught and surfaced as `evidence.parseError`. |
| CheckReport → returned string (formatTerminal/formatMarkdownGuide) | Output strings include only known field names from the structured records plus paths that have already been workspace-normalized. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-15-02-01 | Tampering | Path traversal via crafted flow YAML reference | mitigate | Always `path.join(repoRoot, relative)`; reject `relative` that begins with `/` or contains `..` segments after normalization. RESEARCH.md §"Known Threat Patterns" row 1. |
| T-15-02-02 | Information Disclosure | Absolute home paths leaked into repair-guide Markdown | mitigate | Render the literal `~` token; never call `os.homedir()` for any string included in the report output. Acceptance criteria assert this. |
| T-15-02-03 | Tampering by omission | Stale repair guide misleads next run | accept (in this module) | This module is pure; deletion of stale guide on success lives in Plan 03 (`runAndReport` in bin/adp.js). Document the contract in the module header. |
| T-15-02-04 | Input Validation | Malformed flow YAML or ledger JSON | mitigate | Wrap `parseYaml` and `JSON.parse` in try/catch (mirrors handleDoctor pattern); capture `e.message` into `evidence.parseError`; never re-throw to caller. |
| T-15-02-05 | Elevation of Privilege | `pre.check` shell execution via validatePrerequisites | accept | Out of scope to fix; the trust contract for `pre.check` is set by the shipped flow definition only. Documented in RESEARCH.md §"Known Threat Patterns" row 2. |
| T-15-02-SC | Tampering | Supply chain | accept | No new packages added. |

</threat_model>
