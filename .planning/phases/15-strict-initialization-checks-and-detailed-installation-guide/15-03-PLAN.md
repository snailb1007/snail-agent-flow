## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-15-03-01 | Tampering | Repair-guide write target | mitigate | `guidePath` is a constant `path.join(repoRoot, '.ai/state/repair-guide.md')` — no user-controlled path component. `fs.mkdirSync({ recursive: true })` then `fs.writeFileSync` with explicit `'utf8'`. |
| T-15-03-02 | Tampering by omission | Stale repair guide misleads next run | mitigate | On success, `runAndReport` deletes the guide if present (Pitfall 5). Acceptance criteria asserts deletion. |
| T-15-03-03 | Denial of Service | `handleRun` callers blocked by spurious strict failures | mitigate | Run gitnexus impact on `handleInit` before editing; surface any HIGH risk callers per CLAUDE.md GitNexus rule. `handleRun` chain documented in RESEARCH.md Assumption A5. |
| T-15-03-04 | Tampering | Strict checks overwriting user files | mitigate | Helper performs ONLY one write (the repair guide) and one optional unlink (also the repair guide). Source-grep acceptance criterion confirms no other writes were introduced in `handleDoctor`. |
| T-15-03-05 | Information Disclosure | `console.error` lines containing absolute paths | mitigate | The error line uses the literal relative path `.ai/state/repair-guide.md`. No `process.env` or `os.homedir()` is logged. |
| T-15-03-06 | Availability | False-positive strict failure blocks legitimate user | mitigate | `ADP_NO_STRICT=1` env override skips strict checks with a stderr warning (CEO review F2). Default behavior is unchanged. Documented in README. |
