  <action>
    Implement `lib/ownership-store.js` as a CommonJS module with `'use strict';`. Export a class `OwnershipStore` that accepts `dirPath` (absolute path) in its constructor.

    1. Path Traversal Guard:
       In every method (`acquire`, `release`), resolve and validate the lock path. Ensure the `key` is a valid filename slug matching `^[a-zA-Z0-9_-]+$`. If not, throw a standard `Error` with `.code = 'INVALID_ARGUMENT'`.

    2. `acquire(key, owner, options = {})`:
       - Construct `lockFilePath = path.join(this.dirPath, key + '.json')`.
       - Implement an acquisition loop to handle retries during stale-stealing:
         - Try to atomically create and open the file: `const fd = fs.openSync(lockFilePath, 'wx')`.
         - If this succeeds:
           - Close the file descriptor immediately: `fs.closeSync(fd)`.
           - Prepare the metadata object:
             ```javascript
             {
               owner: owner,
               pid: process.pid,
               acquired_at: new Date().toISOString(),
               stale_lock_cap_seconds: options.staleLockCapSeconds || 3600,
               purpose: options.purpose || null
             }
             ```
           - Write this JSON payload to a temporary file path: `const tmpPath = lockFilePath + '.' + process.pid + '.' + Date.now() + '.tmp'`.
           - Call `fs.writeFileSync(tmpPath, JSON.stringify(metadata, null, 2), 'utf8')`.
           - Atomically replace the empty lock file with the metadata: `fs.renameSync(tmpPath, lockFilePath)`.
           - Return `true`.
         - If `fs.openSync` throws `EEXIST` (already exists):
           - Read and parse the existing file: `const content = fs.readFileSync(lockFilePath, 'utf8')`.
           - Check if lock is stale:
             - Failed `JSON.parse` or empty contents -> stale.
             - Malformed or missing `pid` -> stale.
             - Process dead check: `process.kill(metadata.pid, 0)` under try/catch. If it throws `ESRCH`, it's dead -> stale. If it returns or throws `EPERM`, it's alive -> not stale.
             - TTL check: Check if `(Date.now() - new Date(metadata.acquired_at).getTime()) / 1000 > metadata.stale_lock_cap_seconds` -> stale.
           - If NOT stale, throw standard `Error` with `.code = 'LOCK_UNAVAILABLE'`.
           - If IS stale, perform **race-proof stealing**:
             - Try to atomically move the stale lock file to a unique trash path:
               `const trashPath = lockFilePath + '.trash.' + process.pid + '.' + Date.now()`
               `fs.renameSync(lockFilePath, trashPath)`
             - If this throws `ENOENT`, another process won the race and stole or cleared the lock. Retry the acquisition loop.
             - If this succeeds, proceed to create the lock file using the standard exclusive-write pattern (`fs.openSync(..., 'wx')`).

    3. `release(key, owner)`:
       - Construct `lockFilePath`.
       - If `!fs.existsSync(lockFilePath)`, return `false`.
       - Read and parse the file. If parsing fails, proceed to delete it.
       - If metadata `owner` does not match `owner`, throw standard `Error` with `.code = 'OWNER_MISMATCH'`.
       - Otherwise, unlink the file: `fs.unlinkSync(lockFilePath)` and return `true`.

    4. `list()`:
       - If directory does not exist, return `[]`.
       - Read directory contents via `fs.readdirSync`.
       - Filter for files ending with `.json`.
       - For each file, read and parse it within try/catch.
       - Skip empty, corrupted, or stale locks (dead PID or expired TTL).
       - Return an array of parsed lock records, adding a `key` field (the filename without `.json`).
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI client / Caller → lib/ownership-store.js | Key strings and owner strings passed as input parameters are untrusted and must be checked to prevent path traversal outside the locks/claims directories. |
| Filesystem → lib/ownership-store.js | Lock files stored in `.ai/claims/` or `.ai/locks/` are read back and parsed. If corrupted, they must not crash the calling process. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-18.1-01 | Tampering | Lock File Key (path traversal) | mitigate | validate the `key` parameter to only allow safe slug characters matching `^[a-zA-Z0-9_-]+$`. Reject any input containing `/`, `\`, `..` or non-matching characters with an `INVALID_ARGUMENT` error. |
| T-18.1-02 | Denial of Service | Corrupt Lock File | mitigate | Wrap `JSON.parse` of lock file contents in a try/catch block. If parsing throws an error, treat the lock file as stale and permit stealing rather than throwing a syntax exception. |
| T-18.1-03 | Denial of Service | Stuck Active Locks (deadlock) | mitigate | Check recorded PID using portable process signals (`process.kill(pid, 0)`) and enforce a time cap (TTL) using `stale_lock_cap_seconds`. If the PID is dead or the time cap is exceeded, the lock is treated as stale. |
| T-18.1-04 | Tampering / Concurrency | Overwriting Stale Lock (Race condition) | mitigate | When stealing a stale lock, call `fs.renameSync` to move the stale lock to a unique trash path before writing the new lock. A process that fails the rename due to `ENOENT` realizes it lost the race and retries/fails. |
</threat_model>
