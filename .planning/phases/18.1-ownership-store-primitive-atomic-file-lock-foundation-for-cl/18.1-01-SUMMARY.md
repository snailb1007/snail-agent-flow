# Summary — Ownership Store Primitive (Atomic File Lock Foundation)

## Findings verified

- Exclusive lock acquisition uses `fs.openSync(path, 'wx')` to ensure OS kernel-level atomicity.
- Crash-safe metadata writes write the JSON payload containing owner, pid, and timestamps to a unique temporary file first, then atomically replace the target lock file using `fs.renameSync`.
- Lazy stale-steal successfully identifies stale locks via empty/corrupt JSON, dead process checks using portable process signals (`process.kill(pid, 0)`), or exceeded `stale_lock_cap_seconds` time caps (TTL).
- Race-proof stale-stealing is implemented by renaming the stale lock file to a unique `.trash` path using `fs.renameSync` before claiming, ensuring only one concurrent process wins the steal race.
- Release command checks ownership and throws `OWNER_MISMATCH` if the owner does not match, and returns `false` if the lock file does not exist.
- `list()` filters and returns active lock records while ignoring empty, corrupt, or stale lock files.
- Static sanity checks and CLI initialization bootstrap `.ai/claims` and `.ai/locks` directories idempotently.
- `adp doctor` outputs active claims and active locks count.
